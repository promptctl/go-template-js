# Conformance fixtures

Each subdirectory is one fixture: `template.tmpl` + optional `scope.json` +
exactly one expected-outcome file.

## Expected-outcome variants

A fixture has **exactly one** of:

- `expected.txt` — byte-equality parity with Go's `text/template + sprig`.
  Generated by `pnpm conformance:regen`. Asserted by the string-mode harness
  (`test/conformance/string-mode.test.ts`).
- `expected-go-error.txt` — refusal parity: Go declines to execute the
  template, and the engine must decline with the same message. Holds Go's
  message with its `template: <loc>: executing …` wrapper stripped — the
  wrapper is what the engine carries as structured `pos` and renders with
  its own caret, so pinning it would pin Go's error *formatting* rather
  than its verdict. **Declare it, then generate it**: create the file
  empty and run `pnpm conformance:regen` to fill it. Asserted by the
  refusal-parity harness in `test/conformance/string-mode.test.ts`.
- `expected-fragments.json` — structural equality on the typed-T fragment
  list. Asserted by `test/conformance/typed-fragment.test.ts`. JS-only;
  the Go generator skips these.
- `expected-error.json` — error parity: the engine must throw the named
  error. Shape: `{ "kind": "TypeMismatchError", "funcName": "...", "argIndex": N }`.
  Asserted by `test/conformance/error-parity.test.ts`. JS-only; the Go
  generator skips these.

There is no skip-list and no divergence file. A fixture either succeeds
with one of the parity contracts above or it does not exist.

## Coverage strategy for `negative-*` fixtures

The `negative-*` fixtures here are **end-to-end samples** of the
no-silent-flatten guarantee — one fixture per representative func
across the surface (sprig strings, sprig math, sprig regex, sprig
defaults, builtins). They prove the gate fires through the parser →
evaluator → error path on a real template.

The **universal property** — that *every* registered func with a
non-`"any"`, non-`"T"` `argTypes` slot rejects a typed-T fragment in
that slot — is asserted directly against `enforceArgTypes` by
`test/conformance/no-silent-flatten-universal.test.ts`. That harness
iterates the merged FuncMap (default builtins + every sprig category)
and checks each declared slot mechanically. Adding a new sprig func or
builtin grows that test's case count automatically; no fixture
authoring required.

Per-fixture authoring is therefore reserved for cases where
end-to-end behavior matters (parser, pipe arity, error-message
shape).

## Naming convention

`<category>-<short-description>/` where category is one of:

- `controlflow` — if / range / with / define / template / block constructs
- `builtin` — Go template runtime built-ins (eq/lt/and/len/index/slice/printf/call/...)
- `sprig` — Sprig-subset functions (one per category, plus highlights)
- `edge` — whitespace trim, comments, deeply nested, etc.
- `typed` — generic-T fragment behaviour (uses `tagAs`)
- `negative` — fixtures asserting a template is refused: the
  no-silent-flatten guard firing (`expected-error.json`), or Go's own
  refusal reproduced message-for-message (`expected-go-error.txt`)

## Adding a fixture

1. Create the subdir with `template.tmpl`.
2. Add `scope.json` if the template needs scope (omit for nil-scope templates).
3. Add exactly one expected-outcome file:
   - For Go-parity fixtures: run `pnpm conformance:regen` to generate `expected.txt`.
   - For Go-refusal fixtures: create an empty `expected-go-error.txt`, then
     run `pnpm conformance:regen` to fill it.
   - For typed-fragment fixtures: hand-author `expected-fragments.json`.
   - For error-parity fixtures: hand-author `expected-error.json`.

Never hand-write the content of `expected.txt` or `expected-go-error.txt`.
Go is the only authority on both, and the generator is how it speaks; a
hand-typed expected value is a second clock that only ever drifts.
Declaring the *outcome kind* is the author's job, recording the *outcome*
is Go's — so regen fails loudly if a fixture declares a refusal Go does
not make, or makes a refusal the fixture did not declare.
4. The matching harness under `test/conformance/` will pick the fixture up
   automatically — no test code change required.

## Avoid

Patterns that won't byte-match Go:

- Regex with lookbehind or Unicode property escapes.
- Float formatting at extreme precision.
- Bare `range` over a map (Go's map iteration is randomized; JS object
  iteration is insertion-ordered). Sort the keys first if you need it.
